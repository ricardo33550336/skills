# ODD 验货工作流

本 skill 把 ODD 框架变成 AI 编码时的操作纪律。**核心：先定义"什么算对"，再生成实现；没有 oracle 的代码不许静默进入主路径。**

框架全貌见本仓库 `docs/ODD框架-v2-优化版.md`（项目内安装时也可能是项目根目录同名文件）。本文件是可执行门禁流程；存量/增量的专项路线、阶段退出标准见对应 playbook。

## 第 0 步：识别项目类型

- **存量（brownfield）**：已有运行中的管线/插件，规则埋在老代码、事故记录、日志里 → 读 `references/brownfield-playbook.md`
- **增量（greenfield）**：新插件/新管线/新服务，无历史包袱 → 读 `references/greenfield-playbook.md`
- **混合**（老系统里长新插件）：按存量处理；新插件的 CI 骨架部分可引用增量 playbook。

## 第 1 步：改动半径检查（硬门禁，先判后写）

生成或修改任何代码前，判定改动落在哪一侧：

| 允许 AI 自主改动 | 必须停下叫人 |
|---|---|
| adapter 内部实现（超时/重试/错误处理细节） | 契约 / schema / 接口变更 |
| core 纯逻辑（转换、路由、幂等键计算） | 跨层重构（动 port 接口或目录边界） |
| 快层检查、回放样本、对账断言 | 对依赖方提出验货接口要求 |
| 可观测埋点（错误分类、trace 字段） | 探索性代码转正式（摘除 exploratory 标记） |

**越界即停**：不改、不猜，输出"越界说明 + 建议方案"交人决策。

## 第 2 步：Oracle 存在性检查（硬门禁）

对本次改动问：**"有没有可执行的机制判断改完后算对？"** 按优先级确认：

1. **显式 oracle**：已有断言/对账（主键唯一、金额汇总、行数阈值）→ 直接用
2. **隐式 oracle**：有旧实现/参照路径 → 差分对比（同输入同输出），旧实现即 oracle
3. **蜕变关系**：无精确预期但有性质（重跑幂等、单调性、边界变化规律）→ 写性质断言
4. **都没有** → 两条路：
   - 业务已定型：**停下，先和人把 oracle 写出来**（元数据模板见下）
   - 业务未定型：允许生成，但必须标注 `exploratory: true` + `expires_at` + owner，且不得进入灰度/放量路径

**探索性代码规则**：豁免灰/金门禁，但快层（类型/契约/冒烟）必须过；到期未定型自动标黄。

## 第 3 步：分层路由（决定至少要过哪几层）

| 改动类型 | 快层 | 伪慢层 | 真慢层 |
|---|---|---|---|
| core 纯逻辑 | 必过 | 行为等价/回放 必过 | — |
| adapter 实现 | 必过 | 契约回放 必过 | 热路径才过（影子） |
| 契约变更 | 必过 | 双方回放 必过 | 必过（对账+影子） |
| 冷热分区/口径规则 | 必过 | 边界样本 必过 | 必过（分区对账） |
| 依赖升级 | 必过 | 契约探针比对 必过 | 版本矩阵门禁 必过 |

各层工具基线：
- **快层**：`pyright`（严格模式）、`ruff`、`pytest` + 导入/注册/初始化冒烟（不调真实网络）
- **伪慢层**：`pytest-recording`/VCR 回放、`testcontainers`（本地 Postgres/Kafka）、差分对比脚本
- **真慢层**：影子运行对比、行数/金额/主键对账、契约探针（`/contract-probe`）

## 第 4 步：执行 红→绿→灰→金，并做归因

- **红**：先确认 oracle 对当前代码失败（或差异已登记白名单）
- **绿**：生成实现，过快层
- **灰**：伪慢层回放/差分通过；差异全部可归因（预期内差异要有白名单说明）
- **金**：真慢层对账/影子通过
- **回流**：任何一层失败，归因到四类之一并记录：**oracle 缺失 / oracle 过期 / 样本过期 / 实现 bug**。前两类必须写回 oracle 注册表——不是修完就完。

## 第 5 步：输出纪律（每次任务结束输出三段）

1. **改了什么**：层次、文件、是否越界
2. **过了哪几层**：每层一句话结果 + 未过层的豁免理由
3. **oracle 变化**：新增/更新/标黄的 oracle 及元数据

## 反模式（见到即纠正）

盲迭代（无 oracle 生成实现）· 假绿（放过过期断言/过期录制）· 宽依赖裸奔（插件直连新 SDK 不进 adapter）· 快层碰真实环境 · 只验代码不验数据口径 · 越界改动不报告 · 把失败全归因成"实现 bug"（逃避 oracle 问题）· 探索性代码无到期时间。

## Oracle 元数据模板

每个新 oracle 必须随代码登记（YAML 头或注册表条目）：

```yaml
id: oracle-xxx
assertion: <可执行断言或对账规则>
source: <事故/合规/财务口径/契约/代码提取，具体到可追溯对象>
owner: <人>
decay_condition: <什么变化说明它可能失效>
last_verified: <日期>
confidence: confirmed | extracted   # extracted = 从存量代码提取的行为快照，待业务确认
exploratory: false                  # true 则必须带 expires_at
```
